Line and ownership policy

The limit is a review trigger, not a reason to produce shallow wrappers. Files are split where a separate owner or lifecycle exists.

Applied project-wide

Normal rule

  • Prefer 250–400 lines for implementation files.
  • Review files as they approach 500 lines.
  • Keep one meaningful external seam per deep module.
  • CSS and generated Prisma code are excluded.

Reviewed exceptions

  • useSaleWorkflow.ts — 550 cohesive lifecycle lines.
  • usePurchaseWorkflow.ts — 545 cohesive lifecycle lines.
  • Both remain under the explicitly agreed rare-exception ceiling.
Contracts preserved Database schema and HTTP contracts were unchanged, and no runtime dependency was added.
